# Skill: Business Analysis
1. Read the request, existing SRS/tickets and relevant legacy screens.
2. Identify actor, goal, preconditions, main flow, alternate flows and failure cases.
3. Verify business rules against authoritative backend behavior/product owner.
4. Identify data fields, state transitions, permissions and side effects.
5. Write testable acceptance criteria and negative scenarios.
6. Link requirement → business rule → API → screen/component → test.
7. Label unknowns and conflicts; never fill gaps with assumptions.
Output: feature brief, acceptance criteria, traceability entries and open questions.
